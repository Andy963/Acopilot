# ADR 0001: Record Architecture Decisions

- Status: Accepted
- Date: 2026-01-29

## 背景

本项目包含较多“隐含约束”的决策点，例如：工具系统的执行与展示边界、安全策略、跨消息渲染规则、以及与发布流程的耦合方式等。

仅靠 PR/commit message 与 `CHANGELOG.md` 往往只能回答“做了什么”，难以在半年后快速回答“当时为什么这么做、替代方案是什么、做出的权衡是什么”。

## 决策

采用 ADR 机制，并约定：

- ADR 统一存放在 `docs/adr/`。
- 每条 ADR 记录一个“可复盘的决策点”，包含：背景、约束、决策、后果、替代方案。
- 当某个决策被推翻时，不修改旧 ADR 的结论；新增一条 ADR，并将旧 ADR 标记为 `Superseded`。

## 影响

- 正向：降低长期维护成本；新加入的维护者可以在较短时间内理解关键决策与取舍；减少“重复讨论”。
- 负向：需要维护 discipline；ADR 过多时需要维护索引与可检索性（可通过命名规范与定期整理缓解）。
