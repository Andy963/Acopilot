## 2025-03-19 - [Fix] Command Risk Assessment Bypass via Shell Operators
**Vulnerability:** The application assessed shell command risks using regex patterns bound only to the start of a string or whitespace (`(^|\s)`). This allowed dangerous commands (like `rm -rf /`) to bypass the risk assessment if they immediately followed shell operators like `;`, `&&`, `|`, `` ` ``, or were executed in a subshell `$(...)` without leading spaces.
**Learning:** Command string parsing for security validation must account for all shell operators and delimiters (e.g., `;`, `&`, `|`, `` ` ``, `$()`, `{}`) rather than simply relying on word boundaries and whitespace. Shell metacharacters effectively act as word boundaries for executable commands.
**Prevention:** Use a comprehensive regex boundary (`(^|[\s;&|`({])`) to catch potentially dangerous commands irrespective of the shell operators preceding them. Additionally, validate against common execution obfuscation patterns like backticks and subshells.
